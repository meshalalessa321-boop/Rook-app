# Meridian

Meridian is a private engineering command center with durable tasks, persistent project memory, run records, an owner approval queue, and a continuously running worker loop.

## Implemented

- FastAPI app and owner-token-protected API.
- PostgreSQL persistence on the host; SQLite is available for local development.
- Separate records for tasks, memories, chat history, run evidence, and approvals.
- A polling worker that resumes queued tasks, requeues interrupted tasks after restart, records runs, and reports a missing model key instead of pretending to be active.
- Tool-enabled model reasoning: read and list files from explicitly allow-listed repositories, search repository paths, create tasks, record memory, and submit proposed file replacements.
- Proposed changes are not written to GitHub until the owner approves them. Approval creates a separate branch and a draft pull request. Meridian never merges automatically.
- GitHub credentials stay server-side; the browser receives no GitHub or model API keys.
- Health endpoint, deployment blueprint, and automated safety tests.

## Rook safety boundary

Meridian is an engineering agent, not Rook's model. It must not replace Rook's randomly initialized or trained weights. The allow-list defaults to meshalalessa321-boop/Rook-app. The tools do not give the model a direct file-write or merge tool; it can only propose changes for explicit approval. Repository file content is untrusted input, not system instructions.

## Deployment

The root render.yaml blueprint describes a Python web service and a PostgreSQL database in Singapore. The service is configured for an always-on Starter plan; the database is a small paid plan. This blueprint is code only; it does not create resources until deployed in the Render account. Check current pricing and choose the workspace before deploying. Model API usage is billed separately.

The deployment requires these server-side values:
- MERIDIAN_ACCESS_TOKEN: generated by Render in the blueprint. This is the owner login token.
- OPENAI_API_KEY: the secret for Meridian's model provider.
- GITHUB_TOKEN: a fine-grained token limited to meshalalessa321-boop/Rook-app, with contents read/write and pull-request creation permissions. The worker does not need repository administration permissions.
- DATABASE_URL: set automatically by Render.

Never commit actual tokens or paste them into chat. The public /health endpoint intentionally reveals only that the web process responds. All useful API routes require the owner token.

## Local development

Use Python 3.12 or later.

    cd meridian
    python -m venv .venv
    . .venv/bin/activate
    pip install -r requirements.txt
    cp .env.example .env
    uvicorn app:app --reload --port 10000

If OPENAI_API_KEY is absent, the service stays available for local task/memory use but the worker reports waiting_for_model and will not claim task completion. Add the actual key through your local environment or hosting secret store, never source control.

## Checks

Run python -m compileall -q app.py, pytest -q tests, and node --check static/app.js. The workflow validates these on pushes and pull requests affecting Meridian.
